# CleanDDD 需求分析技能

## 使用时机

- 需求还比较散，尚未做结构化拆解
- 需要先区分干系人、业务实体和动作，再进入建模

## 工作流

1. 获取与确认范围
2. 识别干系人与目标
3. 拆分需求条目并编号
4. 归类业务实体与职责
5. 提炼“当 X 时做 Y”的触发关系
6. 补充约束、依赖、输入输出与假设
7. 汇总并二次确认

## 输出格式

- 干系人表
- 需求条目表
- 业务实体视图
- 触发/后续动作表
- 业务规则与依赖
- 假设与待确认清单

## 边界要求

- 停留在需求级，不提前引入聚合、命令等实现术语
- 产出应能直接作为 `cleanddd-modeling` 的输入
