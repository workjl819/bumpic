# PRD

## 适用范围

- 适用于当前仓库 `docs/` 下所有 PRD 文档
- 当任务是“生成 PRD”“补 PRD”“重写 PRD”时，优先遵循本规则

## 章节模板

- 当前项目的 PRD 默认只保留以下 8 个一级条目，按顺序输出：
  - `1. 文档目的`
  - `2. 背景`
  - `3. 需求条目`
  - `4. 核心流程`
  - `5. 触发关系与后续动作`
  - `6. 业务规则与依赖`
  - `7. 接口影响范围`
  - `8. 页面范围`

## 编写要求

- 一级标题统一使用阿拉伯数字编号
- 若存在子章节，子章节编号应与一级标题保持连续，例如 `4.1`、`4.2`
- 不额外新增“目标”“非目标”“干系人”“验收标准”“假设与待确认”等一级条目，除非用户明确要求
- `3. 需求条目` 优先使用表格表达，包含“编号 / 需求 / 说明”
- `4. 核心流程` 优先使用编号步骤
- `5. 触发关系与后续动作` 优先使用表格表达，包含“触发事件 / 系统动作 / 后续结果”
- `6. 业务规则与依赖` 可按主题拆分子章节，例如注册规则、登录规则、忘记密码规则
- `7. 接口影响范围` 按“需改造接口 / 拟新增接口”组织；如果没有对应内容，可省略子章节但保留一级条目
- `8. 页面范围` 只描述页面与字段范围，不扩展到实现设计

## 内容边界

- PRD 停留在产品需求层，不提前展开聚合、命令、查询、仓储、数据库迁移等实现细节
- 允许引用现有接口路径，但不要在 PRD 中写过多代码级实现约束
- 若已有存量字段或存量接口不打算本期改动，应明确写“暂时保留，不删除”或同等语义

## 默认约定

- 文档标题格式优先使用 `{主题} PRD`
- 文档头部优先保留版本表与项目说明
- 若用户未指定更复杂结构，则默认按本规则生成最小 PRD
