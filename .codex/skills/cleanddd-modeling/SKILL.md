# CleanDDD 建模技能

## 使用时机

- 已经完成需求澄清，准备进入模型设计
- 需要把需求条目转成聚合、命令、查询、事件和 Endpoint

## 前置输入

- 优先先有 `cleanddd-requirements-analysis` 的输出
- 至少明确干系人、需求条目、业务实体、触发与后续动作

## 工作流

1. 校验输入是否完整
2. 定义聚合边界、不变式、实体和值对象
3. 映射命令与查询
4. 列出领域事件与事件处理器
5. 设计外部 Endpoint、鉴权与幂等性
6. 如有周期需求，再补定时任务模型
7. 标明假设与未决问题

## 输出格式

- 聚合：名称、职责、关键不变式
- 命令：名称、输入、输出、幂等性
- 查询：过滤、排序、分页、输出 DTO
- 事件处理器：领域事件、订阅方、动作、副作用
- Endpoint：路径、方法、命令或查询、鉴权、幂等性
- 定时任务：名称、频率、触发动作

## 关键约束

- 聚合之间不直接引用实体
- 领域事件使用过去式
- 命令/查询/事件/Endpoint 均使用 PascalCase
- 输出结果应能直接承接到 `cleanddd-dotnet-coding`
